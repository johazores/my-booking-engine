# Authenticated inventory form ingress

All currently implemented inventory mutation routes use `readInventoryFormData()` from `src/server/inventory/inventory-http.ts`, after the shared same-origin, supported-form-media-type, authenticated-session, and active-organization checks. The reader now delegates to the dependency-free bounded parser in `src/server/http/bounded-form-body.ts` through the inventory compatibility wrapper in `src/server/inventory/inventory-form-body.ts` instead of calling unbounded `request.formData()` directly.

The parser accepts browser `application/x-www-form-urlencoded` and `multipart/form-data` **text-only** submissions. It rejects malformed or unsupported content types, missing bodies, invalid or excessive advertised `Content-Length`, actual streamed bodies larger than 64 KiB even when the header lies or is absent, invalid UTF-8, malformed multipart payloads, uploaded files, duplicate field names, field names longer than 100 characters, and more than 64 distinct fields. Invalid submissions preserve the existing inventory mutation `error=validation` redirect; they do not reach inventory services or produce a success audit. The 64 KiB ceiling includes multipart boundaries and headers, not just form values.

The shared `formField()` reader continues to return scalar text values and an empty string for absent keys. Inventory services still enforce current tenant membership, capabilities, tenant/resource ownership, lifecycle, concurrency, and domain validation. These transport limits are defense in depth, not a replacement for server-side authorization or business validation. Inventory image management currently stores validated external URL metadata; these routes do not accept uploaded media binaries.

`src/server/inventory/inventory-form-body.test.ts` covers normal URL-encoded and multipart forms, invalid/oversized declared and actual bodies, malformed encoding and multipart input, uploaded files, duplicate keys, and field-count limits. `scripts/inventory-form-ingress-contract.test.mjs` prevents inventory route handlers from bypassing the shared reader. The full Node 24/TypeScript 6/lint/build and disposable PostgreSQL gates remain required before claiming full production validation; GitHub Actions are not used.

The shared parser also rejects malformed percent escapes and percent-encoded invalid UTF-8, embedded NUL, empty field names, and inconsistent advertised body lengths. The throwing adapter is used by other browser mutation routes to preserve their existing validation-error handling. These checks are independent of tenant authorization.

The shared form reader also caps streaming at 16,384 chunks independently of its 64 KiB byte limit, so endless empty or tiny chunks cannot consume unlimited processing. When a body exceeds its declared/actual byte limit or chunk ceiling, streamed bytes are copied immediately into one bounded growable buffer using native typed-array operations, so reused or shadowed chunk objects cannot rewrite or miscount accepted data. Upstream cancellation is best-effort and is not awaited: a stalled cancellation promise cannot hold the mutation request open. Regression tests cover these cases; existing server-side permission checks remain unchanged.
